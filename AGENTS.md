# vault-viewer

A read-only, offline-capable website for one person's Obsidian vault. It is built statically with Astro, hosted on Cloudflare Pages behind Cloudflare Access, and fed by `vaultsync`, a Go CLI that pushes the vault to a private GitHub repo every hour.

## Read before working

1. `CONTEXT.md`: the glossary. Use its terms in code, tests, issues and commits (e.g. **vault file**, **note**, **attachment**, **large file**, **deploy**).
2. `docs/specs/vault-viewer.md`: the full spec. Its user stories, decisions, test seams and 8 milestones are what we build against.
3. `docs/adr/`: decisions that are hard to reverse. If a change contradicts one, say so explicitly instead of quietly working around it.

## Hard rules

- **This repo is public; the vault is private.** Never commit, log, or put in issues or fixtures anything from the real vault: content, note titles, folder names. Test fixtures are made-up vaults. (ADR-0001)
- **$0 is a constraint, not a goal.** Never weaken the R2 storage cap, the no-delete rule in `vaultsync`, or the Access/noindex protections. (ADR-0002, ADR-0005)
- **Test at the four seams only:** the site build against a fixture vault, the `vaultsync` binary, the `/media/*` Function handler, and a Playwright run against the built site. Test what can be observed from outside, never internal helpers. See the spec's Testing Decisions.

## Toolchain

Bun for JS/TS (there is no npm on the dev machine) and Go for `vaultsync`. Local builds read the vault from `VAULT_DIR`.

Where a skill or tool says to run `npx`, run the same command with `bunx`.

### Commands

- `bun install`: install dependencies.
- `VAULT_DIR=/path/to/vault bun run dev`: local preview with reload.
- `VAULT_DIR=/path/to/vault bun run build`: build the site into `dist/`. Without a usable `VAULT_DIR` the build fails and says why.
- `bun test`: the seam-1 build tests. They need no vault: each test builds its own fixture vault.
- CI (`.github/workflows/ci.yml`) runs `bun install --frozen-lockfile`, `bunx tsc --noEmit` and `bun test` on every PR to `main` and every push to it, with no vault and no secrets. PRs must be green before merging.
- `scripts/deploy-m1-wizard.sh`: one-time Cloudflare + Access setup and the manual M1 deploy (re-run to re-check protection). Interactive; it uploads real vault content only after a curl check shows Access turns away unauthenticated requests. Writes `CF_ACCESS_TEAM`, `CF_PAGES_PROJECT`, `CF_PAGES_HOST` to `.env` (no secrets). Its optional stage 9 sets up shared pages: the `SHARE_SECRET` (pasted or generated, set as an Actions secret, passed to that run's build, never saved) and the Access application for `/s/` with a Bypass/Everyone policy, then checks `/s/` is let through and the rest is not.
- `SHARE_SECRET=... bun run build`: build with shared pages (at least 32 characters, or the build fails). Unset, the build logs that sharing is off and writes no shared pages and no Share button.

### Layout

- `src/lib/vault.ts`: the vault reader. Reads `VAULT_DIR` and lists every vault file with its slug, size and `kind` (`note`, `image`, `audio`, `video`, `other`; `kindFor` is the one place kinds are assigned, by extension, so new viewers add kinds there). `VaultFile` is `Note | Attachment`: notes also carry `frontmatter`, `openingHeading` and `shared` (frontmatter `share` is `true` or the string `"true"` in any case: a **shared note**); attachments' contents are never read while listing. Unpublished notes (frontmatter `publish` is `false` or the string `"false"` in any case; anything else, malformed frontmatter included, is published) are dropped right after their frontmatter is parsed, so the resolver, file tree, home counts, raw files and the clash check never see them; don't filter them anywhere else. The build fails, naming both vault paths, when two vault files would write the same output path or one writes a file where the other needs a folder (`outputPathsFor` lists each file's viewer page and raw file; keep it in step when adding output). Folder pages join that check as `Folder/`, so a folder page landing on a vault file's output fails too. It also fails when a vault file's viewer page would land under `/s/` (a file or folder slugged `s`), since `/s/` is outside Access (ADR-0006). The list comes from `git ls-files` when the vault is a git repo, else a folder walk (ADR-0004). It fails closed: a vault with a `.git` entry never falls back to the walk, and any git failure other than "not a git repository" fails the build naming the path and git's error. Pages and layouts call `loadVault()`, which a production build reads once and shares (dev reads afresh each call); don't call `readVault` per page.
- `src/lib/frontmatter.ts`: `parseFrontmatter`; the vault reader puts the result on each note as `frontmatter` (`{}` when missing or malformed).
- `src/lib/note-title.ts`: `noteTitle`, the one place a note's displayed title is chosen (frontmatter `title`, else the opening `# Heading`, else file name without `.md`). The page shows it as the one h1.
- `src/lib/opening-heading.ts`: what counts as a note's opening heading (an h1 as the first block after frontmatter): its text for the vault reader, and `remarkTitleHeading`, which makes the rendered body open with exactly one h1 showing the title (the opening heading itself when its text is the title, else a replacement), so rehype-slug ids it like any heading. `renderNote(vault, note, source, { title })` takes the title from `noteTitle`.
- `src/lib/slug.ts`: `slugFor`, the only place a vault path becomes a slug (attachments keep their extension); `viewerUrlFor(slug)`, a viewer page's href; `rawUrlFor(vaultPath)`, a raw file's href (`/raw/<slug>`, `/raw/<slug>.md` for notes); `rawPathFor(vaultPath)`, the same path decoded, for the output file; `folderSlugFor(folderPath)` and `folderUrlFor(folderPath)`, a folder page's slug and href (segments slugged like `slugFor`, but `.md` is never dropped); `sharedPageUrlFor(token)`, a shared page's href (`/s/<token>/`); and `sharedFileUrlFor(token, name)`, a file copied beside it. Slugs keep non-ASCII letters raw (output dirs too), so build every href with `viewerUrlFor`/`rawUrlFor`, never by hand.
- `src/lib/render-note.ts`: our unified pipeline that renders a note to HTML (ADR-0003). New syntax lands here as remark/rehype plugins. An embedded note goes through the same pipeline without its title heading or heading ids: the page it lands in ids every heading once. `src/lib/scroll-tables.ts` wraps every table in a focusable, named scroll region (`div.table-scroll`), so tables keep `display: table`; like heading ids, it runs once on the page, not inside embeds.
- `src/lib/link-resolver.ts`: `resolveLink(vault, fromPath, target)`, the one place a link target becomes a vault file (or `undefined`). Takes a decoded target with no `#fragment`. Obsidian's order: relative to the note's folder, then the vault root, then the shortest vault path ending in the target's whole segments; all three exactly, then all three case-insensitively; each step tries the target as written, then with `.md` appended unless it already ends in `.md`. Its lookups are built once per `Vault` object (WeakMap), so pass the vault from `loadVault()`. Markdown links, images, wikilinks and embeds all use it.
- `src/lib/resolve-links.ts`: `rehypeResolveLinks`, runs after rehype-raw so raw HTML resolves too. Rewrites `a[href]` and `img`/`video`/`audio`/`source[src]` through a `LinkUrls` (`link(file)`, `media(file)`; `OWNER_URLS` gives the viewer page and the raw file; `undefined` makes a broken link). `renderNote` takes `{ urls }` (default `OWNER_URLS`) and passes it to both plugins and every embed. It decodes `%` escapes first and puts any `#fragment` back as written. Targets with a scheme, `//host` or a pure `#anchor` are left alone; any other target that resolves to nothing is a broken link: the element and its text (or `alt`) stay, its `href`/`src` is removed so the target never reaches the output (it may name an unpublished note), and it gets class `broken-link` (styled in `notebook.css`). Never copy the target into another attribute.
- `src/lib/wikilinks.ts`: wikilinks and embeds. `remarkWikilinks` is a micromark syntax extension that parses `[[target#heading|alias]]` and `![[...]]` into `wikiLink` nodes (so code keeps them literal, `\[[` and unclosed or empty `[[` stay text, and `\|` works in tables); remark-rehype and rehype-raw pass the nodes through (`WIKILINK_NODE_TYPES`). `rehypeWikilinks` runs after `rehypeResolveLinks` and replaces each node via `resolveLink`, taking every URL from the same `LinkUrls` (no URL: a broken link): a link to the viewer page (`#heading` becomes the id rehype-slug gives that heading; `^block` refs lead to the note itself; `[[#Heading]]` stays on the page), an embedded image (`|300` or `|300x200` sets its size, other text its alt), `audio`/`video` with `controls` from the raw file, a note's content (or one heading's section) in `div.embed`, lifted out of its paragraph, or for other kinds a link to the viewer page. Embeds stop at a note already being embedded, or 4 notes deep, showing `div.embed-stopped` with a link (just the text where `urls` gives the note no URL). Unresolved ones are `a.broken-link` with no `href`, showing the alias or a fixed label (`broken link`/`broken embed`), never the target.
- `src/lib/share.ts`: shared pages (ADR-0006). `shareSecretFromEnv` (`SHARE_SECRET`; unset means sharing is off; under 32 characters fails the build), `shareTokenFor(secret, vaultPath)` (base64url HMAC-SHA256, first 22 characters = 132 bits), `sharedPages(vault)` (one per shared note, `[]` and one "Sharing is off" log line without a secret), `sharedPageFor(vault, file)`, and `renderSharedPage(vault, page)`: the note rendered with `LinkUrls` that link only to other shared pages and copy images/audio/video under the page as `1.png`, `2.mp3`, ... in order of first use, so no vault path or file name shows in a URL. Memoised per vault, since the page and its files both need it.
- `src/lib/file-tree.ts`: `buildFileTree(files, folderHref?)`, the file tree's data. Arranges any vault files (`{ path, slug }`) into nested folders, folders first, names in natural case-insensitive order; `folderHref` sets each folder's `href`. `findTreeFolder(entries, path)` finds one folder in a built tree.
- `src/lib/folders.ts`: folders, folder index notes and folder pages. `foldersOf(files)` (memoised per file list) gives every folder holding a published vault file, with its `indexNote`, `hasPage` (false only when a sibling `<FolderName>.md` owns the URL) and `href` (the index note's viewer page, else the folder page). The **folder index note** rule, first match, case-insensitive: `Folder/index.md`, `Folder/README.md`, `Folder/<FolderName>.md`, sibling `<FolderName>.md`, else the one direct child note whose name has the whole word "index". `vaultFileTree(files)` is `buildFileTree` with those hrefs: use it wherever a folder is linked (home page, tree, folder pages, breadcrumbs), so all agree.
- `src/components/FileTree.astro`: renders file tree entries as nested `ul` > `li` > `details`/`a`. Opens the current vault file's (or current folder's) ancestor folders and marks its entry `aria-current="page"`. A folder's `li` holds `a.folder-link` (an icon link named "Open <folder>", pinned to the end of the summary's row, before the `details` in source order) and the `details`, whose `summary` only toggles: never put a link inside a summary.
- `src/components/FolderPage.astro`: a folder page's `main`: a `nav[aria-label="Breadcrumbs"]` (Vault, each ancestor to its `href`, the folder itself `aria-current="page"`), the h1, `.folder-index-note` (a card link to the index note, titled by `noteTitle`), then `.home-folders` and `.home-files` like the home page. No `PageActions`: folder pages are owner-only and never shared.
- `src/styles/notebook.css`: the site's global CSS and font imports, used by both layouts.
- `src/layouts/Base.astro`: the layout every owner page uses: `<Base title="..." current="Vault/path.md">` (or `currentFolder="Vault/folder"` on a folder page), with the page's own `<main id="content">` in the default slot (the skip link targets it) and extra `<head>` tags in the `head` slot. Holds the header, the `nav.file-tree` sidebar and its no-JavaScript narrow-screen toggle (checkbox `#file-tree-toggle` + label); its CSS is `src/styles/notebook.css`. Theme: a pastel journal (each page's `body > main` is a card on a faint dot grid) in shadcn/ui's token names (`--background`, `--card`, `--muted`, `--accent`, `--border`, `--ring`, `--sidebar`, ...), all OKLCH, plus six fill-only pastels `--pastel-1`…`--pastel-6` (lavender, mint, peach, sky, rose, butter) that top-level folders take by position; text on a pastel is always `--foreground`. Every colour is a `:root` variable, redefined in full under `@media (prefers-color-scheme: dark)`, with `color-scheme: light dark`; write no colour literals outside those two `:root` blocks (a build test checks this). Non-colour tokens (`--radius`, `--target`, fonts) live on `html`. Fonts are self-hosted `@fontsource-variable` packages imported in `notebook.css` (Figtree for text and interface, Fraunces soft cut for headings and the site name); never link a font CDN (a build test checks this).
- `src/layouts/Shared.astro`: the layout of a shared page and of `404.html`: `body.shared-page` with just the page card (`main#content`), the robots and `no-referrer` metas, and no header, "Vault" link, file tree or download. Visitors are outside Access, so nothing it links or loads may leave `/s/`.
- `src/pages/index.astro`: the home page at `/`, inside `Base` with no `current`. Shows note and vault file counts for the whole vault (notes counted by `kind === "note"`, so attachments count only as files), then the top-level folders (each linking to its folder index note or folder page) and top-level vault files, taken from `vaultFileTree` so names, order and links match the sidebar.
- `src/pages/[...slug].astro`: one viewer page per vault file, at `/<slug>/`, inside `Base`: `PageActions` (with `shareUrl` from `sharedPageFor`), then a rendered note (`main > article.note`) or `AttachmentViewer` (title = file name with extension). Also one folder page per folder with `hasPage`, at `folderUrlFor(path)`: `FolderPage` inside `Base` with `currentFolder`.
- `src/components/PageActions.astro`: a viewer page's action buttons, in the page card's top-right corner (`main.has-actions` gives the card room for them). A `download` link to the vault file's raw file, named with its original file name, and, on a shared note's page when the build shares, a Share button: a plain link to the shared page, enhanced by a small inline script (only on those pages) to `navigator.share`, else copying the absolute URL with a visible "Link copied" `role="status"`. New actions join the same row.
- `src/components/AttachmentViewer.astro`: an attachment's viewer: vault path, human-readable size, and the image inline for `image` kind (its download link is in `PageActions`). Its styles live in the component and use only Base's colour variables.
- `src/pages/raw/[...path].ts`: every vault file's raw file, its exact bytes, at `rawUrlFor(path)`. Reads each whole file into memory (large files move to object storage in M5). `public/_headers` sends `Content-Security-Policy: sandbox` on `/raw/*`, so an HTML or SVG attachment never runs as the site's origin; raw files are not pages and carry no robots meta.
- `src/pages/s/[token]/index.astro` and `src/pages/s/[token]/[name].ts`: each shared page at `/s/<token>/` (inside `Shared`) and the files it shows, from `renderSharedPage`. None without a share secret.
- `src/pages/404.astro`: `404.html`, inside `Shared`. Cloudflare Pages serves the home page for unknown URLs when there is no top-level `404.html`, which under the `/s/` bypass would show anyone the file tree; keep it free of vault content.
- `astro.config.mjs`: static output, trailing-slash directory URLs. Astro handles routing and layout only. Bundled CSS, fonts and scripts go to `/s/_astro/` (`build.assets`), inside the `/s/` Access bypass so shared pages are styled; never bundle anything from the vault. A dev-only integration appends `/` to `/raw/…` and `/s/<token>/<file>` requests, because dev applies `trailingSlash` to those extensionless routes; the build is unaffected.
- `test/harness/site-build.ts`: the seam-1 harness. `buildFixtureVault({ "Path/Note.md": "..." })` writes a made-up vault to a temp dir, commits it to git, runs the real build into its own temp out dir (under the gitignored `.astro/test-builds/`, because Astro renames built assets into the out dir and that fails across filesystems), and returns `{ ok, output, outDir, hasPage(url), page(url), file(path), bytes(path), htmlPages(), outputFiles() }`; `page` returns a DOM document to query with selectors, `file` reads any output file as text (e.g. `_headers`), `bytes` reads one's exact bytes as a `Uint8Array` (paths decoded, e.g. `raw/café.png`), and `htmlPages` lists every `.html` file written (files only, raw files under `raw/` included), as `/`-separated paths relative to the output dir; `outputFiles` lists every file written the same way. `createFixtureVault` + `buildSite({ vaultDir, shareSecret })` split those steps (`vaultDir: null` leaves `VAULT_DIR` unset; `SHARE_SECRET` is unset unless `shareSecret` is given). `buildFixtureVault` and `createFixtureVault` take an optional second argument `{ untracked, deleted, git }` (`buildFixtureVault` also `shareSecret`): `untracked` files are written after the commit, `deleted` paths are removed after it (git still tracks them), and `git: false` makes a plain folder with no repo. Put a `.gitignore` in the files to ignore paths. Call `cleanupTempDirs` in `afterAll`.
- `test/build/`: build tests, one file per feature area.
